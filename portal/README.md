# Кабинет FDV

Сайт и кабинет работают на отдельной службе Node.js. В Linux службе нужны Node.js 20+, Python 3 для SMTP, рабочая копия FDV с WSS и постоянный каталог состояния. Публичные адреса обслуживает Caddy.

- `FDV_PORTAL_ORIGIN` — HTTPS-адрес сайта, например `https://fdvtimer.online`.
- `FDV_PORTAL_INSTANCE_DOMAIN` — зона персональных адресов. По умолчанию `timers.fdvtimer.online`. Для неё нужна wildcard-запись A на VDS.
- `FDV_PORTAL_TIMER_DIR` — каталог файлов серверной сборки. `FDV_PORTAL_STATE_DIR` — отдельный закрытый каталог для учётных записей и состояния экземпляров.
- `FDV_PORTAL_ADMIN_PASSWORD` — начальный пароль пользователя `admin`, минимум 16 символов. Передавайте через закрытый файл окружения службы. После обновления пароля перезапустите службу, чтобы закрыть прежние сессии.
- Для подтверждений по почте задайте `FDV_SMTP_HOST`, `FDV_SMTP_PORT`, `FDV_SMTP_MODE` (`starttls` или `tls`), `FDV_SMTP_FROM` и, если провайдер требует авторизацию, `FDV_SMTP_USER` и `FDV_SMTP_PASSWORD`. Без хоста и отправителя запрос подтверждения отключён.

Кабинет слушает только loopback, по умолчанию порт 9190. Экземпляры используют loopback-порты 9200–9207 и отдельное состояние. На VDS настройки размещаются в `/etc/fdv-portal/portal.env` и `/etc/fdv-portal/smtp.env` с доступом только для root. Публичный прокси направляет HTTPS сайта и HTTPS/WSS персональных доменов в кабинет. При выпуске сертификатов по запросу Caddy проверяет имя через `http://127.0.0.1:9190/_tls/authorize`.

Администратор разрешает регистрацию для конкретного email. Заявку на доступ можно подать с главной страницы. Обязательные поля — ФИО и email. Телефон и комментарий заполняются по желанию. Портал отправляет уведомление администратору. При одобрении адрес добавляется в список разрешённых. При одобрении и отклонении заявителю отправляется письмо. Пользователь подтверждает почту и задаёт пароль. Приостановка аккаунта закрывает сессии, отзывает неиспользованные ссылки и коды и останавливает публичный экземпляр.

После запуска владелец получает HTTPS-адрес и может выдать одноразовый код на 15 минут. Обе стороны должны иметь одну сборку. На локальной стороне нужна версия с полем кода в SEC. Пустота публичного резерва проверяется по сохранённому состоянию, включая скрытые стартовые списки. Последовательность подключения описана в [руководстве](../help.html#hosted-timer) и [описании WSS](../docs/sec-websocket.md).

В кабинете видны состояние сервера, отсчёта и связи SEC. PIN меняется в отдельной панели. «Стоп» запрашивает подтверждение, если идёт отсчёт или действует связь с локальным сервером. Обычный перезапуск и остановка сохраняют состояние. Публичные запросы и перезапуск кабинета оставляют остановленный экземпляр выключенным до нажатия «Запустить». Журнал хранит 30 последних действий управления.

«Перезапустить сервер с очисткой всех данных» требует отдельного подтверждения. Портал останавливает дочерний процесс, очищает каталог экземпляра, меняет токен туннеля, аннулирует одноразовый код и запускает экземпляр с настройками по умолчанию. Учётная запись, история управления, назначенные адреса и гостевая ссылка хранятся в состоянии кабинета.

Перед первым запуском можно указать префикс адреса. Если поле пустое, кабинет выдаёт адрес с префиксом `fdv-` и пятью случайными символами. Короткий адрес меняется через кнопку рядом с публичным HTTPS-адресом. Владелец может оставить прежний адрес рабочим или отключить его. При отключении разрываются соединения экранов и SEC, открытые через этот адрес. Прежний адрес остаётся закреплённым за владельцем и может быть снова выбран в кабинете.

Гостевую ссылку `guest-xxxxx.timers.fdvtimer.online` владелец включает и отключает в кабинете. Значок копирования находится рядом с полем «Адрес». QR открывается в новой вкладке, изображение выдаётся под той же сессией кабинета. Гостевое табло берёт стили и функции подгонки цифр из обычного экрана, показывает номер ротации и поддерживает полноэкранный режим. Отдельный API без регистрации браузера передаёт общий снимок и отметки канонического времени для измерения сетевой задержки. Гостевой адрес не принимает команды управления, сессии браузеров или WSS-подключения SEC.

На действующем VDS `fdv-portal.service` запускается из `/opt/fdv-portal`. Шаблоны и статика лежат в `/opt/fdv-portal/portal`, базовая сборка таймера в `/opt/fdv-portal/timer`, состояние в `/var/lib/fdv-portal`. При обновлении шаблонов и серверного кода нужен перезапуск службы. Он может кратко прервать работу публичных экземпляров, поэтому перед ним проверяют наличие активных отсчётов. Руководство на `help.fdvtimer.online` раздаётся из `/var/www/fdvtimer-help` отдельно от кабинета.

Проверка в рабочей копии:

```sh
node --test test/hosted-portal.test.js
```

Тест использует локальную заглушку доставки. SMTP проверяется отдельно с разрешённым тестовым адресом.

## Изменения

- Усилена синхронизация таймера и звуковых сигналов между экранами. Современные браузеры используют отдельную серверную монотонную шкалу: перевод календарных часов сервера не сдвигает уже запущенный отсчёт и не отменяет запланированные звуковые сигналы. Старт по заданному времени и восстановление после перезапуска сохраняют календарные привязки.
- При первом подключении или после смены серверного процесса экран показывает «Синхронизация времени» и `--:--` до измерения времени сервера. До проверки сигналы не планируются и не отмечаются проигранными. Автономная HTML-версия и Android APK серверной синхронизации не требуют.
- Сообщения SSE доставляют состояние, но не используются как замеры времени: неизвестная задержка доставки больше не может подстроить часы браузера. Пакеты от прежнего серверного процесса и устаревшие ответы не заменяют новое состояние.
- Восстановление сети, часов и аудио обрабатывается раздельно. Обычное возвращение сети или фокуса сохраняет проверенную модель часов и рабочее звуковое расписание. После нарушения непрерывности часов браузер ждёт нового измерения по серверу перед возобновлением сигналов.
- Сохранены алгоритмы оценки скорости часов, сетевые фильтры, прогрев аудиотракта и обычное планирование Web Audio. Дополнены проверки паузы, старта по расписанию, сна, перезапуска сервера и сохранения состояния.
- В Firefox убраны стрелки изменения номера ротации на экране просмотра. В основном браузере при доступном редактировании штатные элементы управления сохранены.
- Обновлены русское и английское руководство, техническая документация, автономная версия и регрессионные тесты.

Сборка приложения: **413**. После обновления перезапустите сервер и обновите все подключённые страницы таймера.

## Changes / English

- Improved timer and sound synchronization across displays. Modern browsers use an independent server monotonic timeline: changing the server calendar clock no longer shifts an active countdown or cancels scheduled sounds. Clock-time starts and restart recovery retain their calendar anchors.
- On first connection or after a server-process change, a display shows “Synchronizing time” and `--:--` until it measures the server clock. Sounds are neither scheduled nor marked as played before verification. Direct standalone HTML and the Android APK do not require a server.
- SSE messages deliver state but cannot calibrate clocks from an unknown delivery delay. Packets from a retired server process and stale responses cannot replace newer state.
- Network, clock and audio recovery are handled separately. Ordinary network reconnection or focus preserves the calibrated clock model and valid sound schedule. A browser-clock discontinuity requires a fresh measured server response before signals resume.
- Retained clock-rate estimation, network filters, audio warm-up and ordinary Web Audio scheduling. Expanded coverage for pause, scheduled starts, suspension, server restart and saved-state recovery.
- Removed native rotation-number arrows from read-only displays in Firefox while retaining normal editing controls in the primary browser.
- Updated both guide languages, technical documentation, standalone output and regression tests.

Application build: **413**. Restart the server after upgrading and reload all connected timer pages.

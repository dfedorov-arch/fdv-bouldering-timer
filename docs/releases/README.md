# Правила описания релизов

Эти правила применяются к описаниям релизов GitHub и файлам с текстами релизов в этом каталоге.

В описании релиза указываем:

- Новую функциональность и её назначение для пользователя.
- Изменения в работе существующей функциональности.
- Исправления ошибок общей фразой: «исправлены незначительные ошибки». При необходимости можно указать область, например: «исправлены незначительные ошибки в работе звука» или «исправлены незначительные ошибки в интерфейсе».

Описание должно быть кратким и понятным пользователю. Подробности отдельных ошибок, их причины, расследования, гипотезы, неподтверждённые сообщения третьих лиц и оговорки об исправлениях, которые выпуск не заявляет, в описание релиза не включаем. Сведения о тестах и технические подробности сохраняем в документации разработки.

Русская и английская версии должны совпадать по смыслу. Для общего сообщения об исправлениях используем английскую формулировку “Minor bugs fixed”, при необходимости с указанием области.

Примеры:

- «Добавлена проверка новых версий в лаунчере».
- «Кнопки лаунчера сгруппированы по назначению».
- «Исправлены незначительные ошибки в работе звука».

Существующие описания не переписываем целиком без отдельного запроса; вносим запрошенные изменения. Для новых описаний соблюдаем правила выше.

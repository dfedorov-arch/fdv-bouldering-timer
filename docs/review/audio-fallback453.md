# Availability-first native/browser fallback — build 453

The owner explicitly accepts two overlapping audio routes in preference to a missing cue. Browser suppression now ends immediately after a native failure is observed; release and state refresh remain asynchronous. The browser uses its last synchronized timeline, unlocks/prewarms locally and restores future/recent cues within existing lateness windows. The 3-second manual-start deadline remains. A deliberate route change retains future-only behavior, and native reacquisition still follows the saved preference. An inactive native event includes the preference so its ordering ahead of the HTTP response cannot misclassify a manual opt-out as failure.

Native cleanup still waits for process termination/watchdog bounds for lease management, but browser playback does not. Native recovery/retry limits are unchanged. Handover to a prepared native route preserves already-playing and near-due browser audio rather than cutting it, accepting a possible overlap. Suppressed browser fallbacks do not mark cues/phase transitions played solely because the native route owned output; this allows bounded recovery of a recent minute cue. Performance records distinguish manual/failure return. This cannot guarantee physical audibility, avoid failure-detection time, or run through an OS/browser suspension.

Validation: 106 focused Node cases pass, including a hanging release and state refresh, immediate opt-out, manual inactive event before action response, bounded retry/recovery, server cleanup ACK and saved preferences. Six Chromium native-route cases pass: manual route persistence/reload, manual return without replay, a native failure with both release/state requests held while the browser plays Start, automatic native return then retention of an explicit browser choice, no expired manual start after 3 seconds, no steady-state duplicate browser playback across native rotations, and unavailable-route recovery (the held-request case combines multiple checks). An additional Chromium case confirms recovery of a recent minute cue suppressed under native ownership. The manual-return and held-request cases were rechecked after adding the recent-cue key guard.

# 01. Обзор проекта

## Назначение

Локальный Node.js-сервер синхронизирует таймер, настройки, браузеры и до четырёх стартовых списков. Один браузер может быть основным; остальные работают экранами. Для старых телевизоров есть облегчённая Legacy-страница, для одиночного использования — автономный HTML.

## Состав

- `serve-bouldering-timer.js` — сервер, API, SSE, снимки, браузеры и диагностика.
- `index.html` — современный интерфейс и автономный клиент.
- `legacy.html`, `lib/legacy-start-list.js`, `lib/start-list-display.js` — старый экран и таблицы.
- `lib/timer-domain.js`, `lib/timer-transitions.js` — чистая логика времени и переходов.
- `lib/client-action-transport.js` — надёжная отправка команд.
- `test/` — модульные, интеграционные и визуальные тесты.
- `scripts/` и `launcher/` — генерация автономных файлов, проверка и сборка portable-релизов.

## Поток данных

Браузер отправляет версионированную команду в `/api/action`. Сервер применяет чистый переход, обновляет версию, сохраняет снимок и уведомляет клиентов через SSE. Периодический `/api/state` даёт резерв доставки и измерения часов. Неизменившиеся большие списки могут не передаваться повторно: клиент использует точное совпадение `startListRevision`.

Основные границы совместимости — `/api/state`, `/api/action`, SSE, сохранённый снимок и Legacy-представление списков.

## Запуск разработки

```powershell
node serve-bouldering-timer.js
npm test
npm run test:visual
```

Пользовательская терминология — «список» / “list”; старое “protocol” допустимо только во внутренних совместимых именах и в HTTP/HTTPS.

# Техническое ревью FDV Bouldering Timer

Обновлено 2026-10-16. Изначальное ревью было написано до появления монотонных серверных часов, восстановления состояния, идемпотентных команд, тестов, ревизий стартовых списков и расширенной диагностики. Старые формулировки «этого нет» больше не являются актуальными.

Документы теперь описывают текущее состояние:

1. [`01-project-overview.md`](01-project-overview.md) — состав и границы приложения.
2. [`02-synchronization.md`](02-synchronization.md) — серверная временная шкала, клиентская синхронизация, офлайн и звук.
3. [`03-bottlenecks.md`](03-bottlenecks.md) — оставшиеся риски, а не уже устранённые проблемы.
4. [`04-improvement-plan.md`](04-improvement-plan.md) — выполненные этапы и актуальный следующий порядок работ.

Канонические подробности: [`../architecture.md`](../architecture.md) и [`../performance-diagnostics.md`](../performance-diagnostics.md).

В develop, сборка 415, добавлен горячий резерв SEC: репликация состояния и монотонной шкалы, обратная передача команд, ручной/автоматический переход и автоматический возврат прежнего основного сервера в роли резерва. Смена ролей требует проверенного обратного доступа и нового поколения полномочий; старые пакеты не принимаются. Актуальный контракт — раздел Hot secondary server в architecture.md. Это асинхронная пара, не консенсус: разделение сети и потеря последней ещё не реплицированной команды остаются явными рисками. Обычный механизм хода времени и планирования звука без SEC не изменён.

# SEC через публичный сервер по WebSocket

Режим связывает один локальный и один публичный сервер FDV одной сборки. Локальный сервер сам открывает соединение по WSS. После смены ролей соединение по-прежнему открывает локальный сервер. Экраны используют обычные HTTP(S)-адреса.

## Экземпляр на fdvtimer.online

В [личном кабинете](https://fdvtimer.online/account) запустите публичный экземпляр и нажмите «Создать код привязки». В основном браузере локального таймера введите в SEC адрес из поля «Адрес для связывания с локальным сервером» и одноразовый код. Обе стороны должны иметь одинаковый номер сборки, а локальная сборка должна поддерживать поле кода в SEC. Кабинет выдаёт код на 15 минут. Настройки окружения и наладка VPN для этого сценария не требуются.

При успешном обмене кодом публичный сервис возвращает токен локальному серверу. Он используется для исходящего WSS и сохраняется вместе с локальной конфигурацией пары. Кабинет блокирует привязку занятого резерва, включая сохранённые стартовые списки, даже если они скрыты в интерфейсе. Очистка публичного экземпляра отзывает прежний код и токен. При смене короткого адреса оставьте прежний адрес рабочим, если по нему идёт существующее соединение. Отключение адреса закрывает туннель и подключения экранов по этому адресу.

Инструкция для оператора находится в [руководстве](../help.html#hosted-timer), а развёртывание кабинета описано в [portal/README.md](../portal/README.md).

## Ручная настройка своего публичного сервера

1. Создайте случайный токен из 32 байтов (64 шестнадцатеричных символа). Например, через `openssl rand -hex 32`. Передайте его обоим процессам FDV в переменной окружения `FDV_SEC_TUNNEL_TOKEN`. Храните токен в настройках запуска серверов с ограниченным доступом.
2. На публичном FDV задайте только токен. Опубликуйте `/api/sec/tunnel` на текущем HTTPS-адресе. Если TLS завершает обратный прокси, передавайте запрос WebSocket с заголовком `Authorization` на FDV через loopback. Для прокси на другом хосте используйте HTTPS до FDV.
3. На локальном FDV дополнительно задайте `FDV_SEC_TUNNEL_URL=wss://timer.example.org/api/sec/tunnel`, подставив домен своего таймера, и перезапустите оба процесса. Открывайте операторский экран по тому адресу локального сервера, который используют экраны площадки.
4. В диалоге SEC укажите соответствующий HTTPS-адрес, например `https://timer.example.org`. Совпадение с публичным адресом из `FDV_SEC_TUNNEL_URL` включает туннель. Для ранее настроенной прямой пары сначала выполните штатное отключение SEC. Публичный узел с включённым приёмом туннеля принимает новые пары через WSS.

Для проверки остановите локальный процесс, дождитесь повышения резерва, измените на нём состояние таймера и запустите локальный процесс. После окна кратковременного восстановления локальный узел должен вернуться в роли резерва и получить изменённое состояние. Отдельно проверьте доступ экранов к публичному адресу и совместимость с HTTPS в браузерах площадки.

Туннель использует существующие проверки SEC, включая ограничение RTT в 500 мс. При полном разделении сети применяются существующие правила выбора основного. Экранам для переключения на публичный FDV нужен доступ в интернет.
